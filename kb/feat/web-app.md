# Web app and WebAssembly bindings (new)

TreeKnit.jl has no browser version. `packages/treeknit-wasm` compiles the core and the formats to WebAssembly, and `packages/web` is a React app that runs an analysis in the browser. [`kb/decisions/web-app.md`](../decisions/web-app.md) records the design decisions.

## WebAssembly bindings

`packages/treeknit-wasm` [[src](../../packages/treeknit-wasm/src/lib.rs)] binds the shared modules of `treeknit-io` (`analysis`, `run`, `output`, `summary`), which the command line uses too. `packages/treeknit-wasm/README.md` lists the interface:

- [x] **`Session.run(request, onProgress)`**: validates with the checks of `validate`, runs on one thread, and calls `onProgress` with each `Progress` of the core [[src](../../packages/treeknit-wasm/src/lib.rs#L145-L199)]. An invalid request throws an `Error` named `ValidationError` whose message joins the messages; an error thrown by `onProgress` stops further progress calls and is thrown after the run
- [x] **`summary()`**: per pair the labels, the tree indices, the MCCs as leaf names, and the counts of imputed and ambiguously attached leaves; the ARG outcome; whether the run shows no reassortment (two trees: the ARG was built with no reassortment; more trees: every pair has one MCC); the diagnostics [[src](../../packages/treeknit-io/src/summary.rs#L26-L56)]
- [x] **Output files**: `files()` lists the session file `treeknit_session.json`, the files of `treeknit --impute --auspice-view --plot` (every tree file with the extension `.nwk`), `parameters.json`, and `log.txt`, each with its download name, media type, and size in bytes (`null` for a figure not yet read); `fileText(path)` returns the text of a listed file, and `zip()` an archive of all of them under `treeknit_results/`. `treeknit_io::output::web_files` defines this file set for both surfaces, and validation rejects a run whose output files of different kinds would get one name [[src](../../packages/treeknit-wasm/src/lib.rs#L210-L251)]
- [x] **`commandLine()`**: the command that writes the same files from the extracted archive into `treeknit_results_cli/`, so the extracted files stay for comparison (see [`formats.md`](formats.md#session-file-treeknit_sessionjson-new))
- [x] **Log capture**: the records of level Debug and above of a run become `log.txt`, in the layout of the command-line log without a thread ID, and its warnings and errors become the diagnostics. Every other export discards its records [[src](../../packages/treeknit-wasm/src/log_capture.rs)]
- [x] **Display data**: `pairView`, `auspiceView`, `argView`, `constellation`, and `drawingRules` (see [Display data](#display-data)) [[src](../../packages/treeknit-wasm/src/lib.rs#L260-L303)]
- [x] **Figures**: `figure(pair, version, options)` and `argFigure(options)` draw SVG figures with the options of the drawing toolbar, and the file list holds the figure files (see [`visualization.md`](visualization.md#figures)) [[src](../../packages/treeknit-wasm/src/lib.rs#L305-L339)]
- [x] **`auspiceFiles(pair, version, scale, trees)`**: the downloads of the Auspice view: the name of its SVG figure and the Auspice v2 dataset of each shown tree as JSON, named `auspice_<a>_<b>` with the version and the shown scale unless they are `resolved` and `div`, and with the tree label for one tree, so they never take the names of the command-line files `auspice_<label>.json` [[src](../../packages/treeknit-io/src/output.rs)]
- [x] **`defaultSettings()`**: the settings of a request without settings, which are the command-line defaults
- [x] **`settingsSchema(k, settings)`**: the default, the bounds, the input step, whether the setting applies with the reason when it does not, and the help text of every setting, and the resolution modes, from `treeknit_io::schema` [[src](../../packages/treeknit-wasm/src/lib.rs#L39-L44)]
- [x] **`inspectTree(label, text)`**: the leaf, internal node, and polytomy counts of one tree, whether its branches have lengths, the parser warnings, and the parse error with its line and column, from `treeknit_io::inspect` [[src](../../packages/treeknit-wasm/src/lib.rs#L46-L51)]
- [x] **`overlap(trees)`**: the leaves of each tree that parses, the leaves that each pair of them shares, and the pairs that share fewer than two leaves [[src](../../packages/treeknit-wasm/src/lib.rs#L53-L67)]
- [x] **`version()`**: the TreeKnit version, the source repository, and its release page (`<repository>/releases`), which Rust derives from the workspace `repository` field [[src](../../packages/treeknit-wasm/src/lib.rs#L113-L118)]
- [x] **`palette()`**: the drawing colors of the light and the dark theme [[src](../../packages/treeknit-wasm/src/lib.rs#L120-L125)]
- [/] **Settings**: `gamma`, `seqLengths`, `nMcmcIt`, `resolve`, `preResolve`, `rounds`, `finalRound`, `likelihood`, `naive`, and `seed` [[src](../../packages/treeknit-io/src/analysis.rs#L53-L84)]. The former method options of the command line and the thread count are not available; analyses run on one thread
- [x] **`validate(request)`**: the checks of the command line [[src](../../packages/treeknit-io/src/analysis.rs#L173-L204)]: at least two trees, labels usable as file names and unique, distinct pair file names, Newick syntax, at least two shared leaves per pair, γ finite and not negative, one finite positive sequence length per tree, at least one and at most 2^32 - 2 rounds, at least one and at most 2^32 - 1 MCMC steps per leaf, and a seed of at most 2^53 - 1. Each error has the camelCase path of its field (`settings.seqLengths[1]`, `trees[0].newick`) and, for a Newick error with a position, the 1-based line and column in characters. A request of the wrong shape (unknown fields, wrong types) throws an error with the JSON position
- [x] **`readSession(text)`**: the request of a session file, `treeknit_session.json`, checked for its JSON structure and a seed of at most 2^53 - 1 only, so a request with a broken tree or an invalid setting loads; throws with the messages otherwise [[src](../../packages/treeknit-io/src/analysis.rs)]
- [x] **`sessionFile(request)`**: the session file of a request, as the output file `treeknit_session.json` (see [`formats.md`](formats.md#session-file-treeknit_sessionjson-new))
- [x] **Links**: `parseLaunch(entries, viewKeys)`, `launchPairs(source)`, `inlineSession(request)`, `applySettings(base, patch)`, `decodeTreeBytes(bytes)`, `launchKeys()`, and `linkLimits()` give the web app the link grammar of `treeknit_io::launch` (see [`formats.md`](formats.md#links-new)), and `examples()` the example catalog of `treeknit_io::examples` [[src](../../packages/treeknit-wasm/src/lib.rs)]
- [x] **`treeLabels(fileNames, existingLabels)`**: labels for new trees: the file name without its last extension, with each character that the label check rejects (path separators, characters reserved on Windows, control characters) replaced by `_`, `tree` for a name that leaves no usable label (empty, blank, `.`, or `..`), and `_2`, `_3` on a collision with an existing or earlier label, ignoring case as the label check does [[src](../../packages/treeknit-io/src/analysis.rs#L386-L425)]. The command line labels by path instead (see [`cli.md`](cli.md#input-validation))
- [x] **TypeScript declarations**: tsify derives them from the Rust types; the generated file is committed and `just generated-check` detects stale declarations
- [x] **Panics**: a panic hook writes the message to the browser console. A panic traps the module

## Display data

`treeknit_io::display` returns the drawable form of the run result; the interactive views and the SVG figures draw the same geometry and only map it to pixels [[src](../../packages/treeknit-io/src/display.rs)]:

- [x] **Pair view**: `pair_view` sorts both trees of a pair on copies with the run's sort (`treeknit_core::pipeline::sort_for_pair`, which always ladderizes the left tree), by the pair's MCCs restricted to the leaves both drawn trees share. The `resolved` version of a pair whose order the run kept (`keeps_run_order`) uses the final trees as they are, so its leaf order equals `<label>_resolved.nwk`. The `imputed` version is sorted by the MCCs with their attached leaves, which both imputed trees hold [[src](../../packages/treeknit-io/src/display/pair.rs#L15-L57)]
- [x] **Tree layout**: nodes in preorder with `xDiv` (missing, negative, or non-finite lengths as 0), `xDepth`, `y` (leaf rank, internal nodes at the midpoint of the first and last child), `added` (an internal node whose name the input tree lacks), `imputed`, the MCC of the Fitch map, `mccBreak`, `cladeSize` (the leaves below the node), and `shortName` (the name shortened to the label length). Node names are unique within a drawn tree: an internal node named like a leaf or an earlier node, which imputation can produce, gets a free name `<name>_<k>` [[src](../../packages/treeknit-io/src/display/tree.rs#L13-L55)]
- [x] **Links and blocks**: one link per leaf with an MCC in both drawn trees; blocks are runs of links of one MCC, consecutive in the left tree and stepping by one row in a constant direction in the right tree [[src](../../packages/treeknit-io/src/display/pair.rs#L122-L204)]
- [x] **MCCs**: index, size, leaves, imputed and ambiguously attached members, and color slot
- [x] **Color slots**: greedy coloring with eight slots over the MCCs whose blocks are consecutive in the left or the right order, largest MCC first. Of the slots that no colored neighbor uses, an MCC takes the one used least so far in the pair (the lowest on ties), so the MCCs spread over all eight colors; a slot is shared with a neighbor only when an MCC has eight or more colored neighbors, then the one least used among them. Computed on the `resolved` version and kept for every version [[src](../../packages/treeknit-io/src/display/slots.rs#L43-L69)]
- [x] **ARG view**: the three top-root cases of `ARG/arg.nwk` (shared root, synthetic `GlobalRoot`, one shared root), x along the chain to the top root (the segment 0 parent when its chain reaches the top root, else the segment 1 parent), leaves in the order of the ARG's segment 0 tree, then of its segment 1 tree, and one reticulation edge per hybrid node: its edge off that chain. Labels are made unique, because a leaf may carry the label of an internal ARG node [[src](../../packages/treeknit-io/src/display/arg_view.rs#L18-L79)]
- [x] **Constellation table**: every taxon (the first tree in its final order, then the leaves it lacks in the order of the first tree that has them) by every pair, with the MCC, its size, and its slot, or none when the pair gives the leaf no MCC [[src](../../packages/treeknit-io/src/display/constellation.rs#L9-L55)]
- [x] **Auspice datasets**: `auspice_view` writes the two trees of a pair view as Auspice v2 datasets for Auspice's tanglegram, with the names, display order, MCCs, and color slots of the pair view. Each node has `div` (`x_div` for the scale `div`, `x_depth` for `depth`) and, when it has an MCC, the attribute `mcc` with the MCC name ("MCC 1" for index 0), `largest_mcc` (the name for the 8 largest MCCs by leaf count, ties in MCC order, else "Other"), and `mcc_size`; every node but the root has `reassortment` (Yes or No), a leaf `imputed`, `one_tree`, and with an MCC `attachment` (Ambiguous or Unambiguous), an internal node `added`; each reassortment branch has the label `MCC` with the MCC number. Both datasets hold these colorings in the light theme colors, because Auspice has no dark theme: `mcc` titled with its pair, `largest_mcc` with the 8 palette colors and the no-MCC color for "Other", the continuous `mcc_size`, and the Yes and No categories in the signal and no-MCC colors; every categorical coloring is a filter. They hold the display defaults color by `mcc` and branch label `MCC`, the axis title ("Divergence" or "Depth"), the node where each MCC starts in each tree (`mcc_roots`), and `sharing.entropy` false, because the datasets have no sequences for the genetic diversity download. Both datasets show the scale of the pair view, which is `depth` for `div` when a tree has no branch lengths (`AuspicePair.scale`). The nesting is built bottom-up, so building a deep tree does not recurse. The command-line files `auspice_<label>.json` are a separate format and stay unchanged [[src](../../packages/treeknit-io/src/display/auspice.rs)]
- [x] **Shapes**: elbows, reassortment rings at branch midpoints, imputed tips, leaders from each leaf tip to the label edge, link S-curves with control points at x = 0.5, closed ribbon outlines with each y range extended by half a row, and ARG edges as elbows or, for reticulation edges, S-curves. Each shape carries the MCC it is drawn for, and each ARG edge shape its segments; x normalized to 0 to 1 per column, y in rows. On the divergence scale the branch of an added node is drawn at least 2% of the tree column long, because resolution inserts its splits with branch length 0; the nodes below it move right by the same amount, so every other branch keeps its drawn length, and the tree is scaled back into its column. The part across of an added branch is drawn in ink-muted, its part along the parent's x like a plain branch [[src](../../packages/treeknit-io/src/display/shapes.rs)]
- [x] **Drawing rules**: `DRAWING_RULES` holds the rules that depend on the drawn size: the thresholds of the row height (labels from 10 px per row, links from 6 px per row), the label length (40 characters, which `DrawNode.short_name` and `ArgNodeView.short_label` apply), the columns of a drawing (16 px margin, 6 px label gap, a link zone of 20% of the inner width minus the label columns and at least 15%, label columns of at most a quarter of half the inner width in a tanglegram and of the inner width in an ARG), and the stroke widths, mark sizes, opacities, and dash patterns; the consumer applies them, and the SVG figures follow them [[src](../../packages/treeknit-io/src/display.rs#L34-L119)]

## Web app

`packages/web` [[src](../../packages/web/src/main.tsx)] runs the analysis in the browser; `packages/web/README.md` describes its modules.

- [x] **Tree input**: dropped, chosen, and pasted files and Newick text, the examples, session files, and links; a reorderable tree list with labels, counts, and errors per tree [[src](../../packages/web/src/inputs/)]
- [x] **Examples**: the Examples menu lists the catalog of `treeknit_io::examples` (`examples()`), grouped as small, real H3N2 data of `data/`, and simulated cases of `fixtures/sim/`; Vite bundles each tree file as its own chunk, loaded by its repository path [[src](../../packages/web/src/analysis/example.ts)]
- [x] **Settings form**: every default, bound, help text, and applicability from `settingsSchema`
- [x] **Run in Web Workers**: a utility worker, one job worker per run, and a session worker for the result (see [`kb/decisions/web-app.md`](../decisions/web-app.md))
- [x] **Results**: the overview, the tanglegram, the Auspice view, the ARG, the MCC table, the constellation table, the files with their downloads and the command line, and the diagnostics
- [x] **Routes (new)**: `/` (the workspace) and `/help` on browser history, with one HTML file per page (`help.html`, a copy of `index.html` that the build writes), because GitHub Pages has no rewrite rules; the router takes its base path from the location of the bundle, so one build works under any path. Old hash links (`#/help?...`) move into the path on load, and `/help#help-cite` opens the help page at that section [[src](../../packages/web/src/pages.ts)]
- [x] **View keys (new)**: `view`, `pair` (`pair=ha:na`, by the labels of the pair in either order), `version`, `scale`, `labels`, `show` (the label of the one tree the Auspice view shows alone), `auspice` (a query string of Auspice's own keys, written with `&` as `%26`), `mcc` (the number on screen, from 1), `leaf`, and `node` (`left:NODE_3`). One zod schema with codecs reads and writes each key, invalid values fall back to their defaults, defaults are not written, and keys the view does not own pass through unchanged [[src](../../packages/web/src/workspace/search.ts)]
- [x] **Links (new)**: at start the app reads the keys of the query and of a fragment with `=`, parses them with `parseLaunch`, and loads the input: an example, `https:` files (without credentials, at most 60 seconds and 64 MiB each, decoded by `decodeTreeBytes`), `data:` texts, a session file, or a session file that the opening page (`from=opener`) or the embedding page (`from=parent`) posts after the app announces `treeknit:ready` every 250 ms for 10 seconds. Once every input has loaded, the workspace is replaced with an undo entry ("Link opened"), or kept without one when it already holds the same request, and `run` starts the run, which stays on the view that the link names [[src](../../packages/web/src/launch/LinkLaunch.ts)]
- [x] **Link notices (new)**: the workspace header shows the loading ("Loading 2 trees from raw.githubusercontent.com"), each failed download with its reason (CORS or network, the HTTP status, the time or size limit) and Retry, and the errors of the link with the ignored keys that have a suggestion or a hint, such as an Auspice key outside `auspice` [[src](../../packages/web/src/launch/LaunchNotices.tsx)]
- [x] **Address bar (new)**: after a launch, the address bar holds the canonical link (`launchPairs`) of the shown result with `run`, or of the current trees and settings before a run; edits after a run leave it until the next run, trees without an address take the input keys out of it, and it never holds an inline session [[src](../../packages/web/src/launch/addressBar.ts)]
- [x] **Copy link (new)**: the run bar copies the address bar when every tree has an address, and otherwise a link with an inline session in the fragment; it shows the length, warns above 2,000 characters, and above 32,000 offers "Save session file" instead [[src](../../packages/web/src/launch/CopyLinkButton.tsx)]
- [x] **Tree origin (new)**: a tree from an address shows its host, and a tree from another page its origin
- [x] **Auspice view (new)**: the view tab "Auspice", after "Tanglegram", draws trees of the run with Auspice 3.0.0, embedded as a library, in the colors and layout of Nextclade's tree page. A strip of tree toggles chooses the shown trees: two trees show their pair as a tanglegram (the left tree as the main tree, the right tree as the second tree, joined by tip name), one tree shows that tree alone with Auspice's other layouts. The view fills its area exactly: the card title row holds the leaf count, the filter summary, "SVG" and "JSON" downloads named by Rust, and one set of zoom buttons for the shown trees. Auspice's controls sit in a collapsible sidebar with a pull tab, which covers the tree when the view is narrower than 900 px: color by (the MCC, the largest MCCs, the MCC size, reassortment branches, imputed leaves, added nodes, leaves of one tree only, the attachment), filters, and with one tree also the layout and the branch metric, focus, branch and tip labels, and with two trees the tangle switch. Color by, filters, labels, legend, and focus stay in the view key `auspice`. The workspace selection marks its leaf or filters to its MCC in the view, a tip click or a Shift click on a branch selects the leaf or node in the inspector, Escape clears the selection, and "Zoom to MCC" zooms each shown tree to where the MCC starts. The datasets come from Rust `Session.auspiceView(pair, version, scale)` in the light palette; Auspice has no dark theme, so the view stays light in the dark theme. A finished run whose result the workspace stores opens this view. The view is loaded on demand as its own chunk [[src](../../packages/web/src/auspice/AuspicePanel.tsx)]
- [x] **Citation (new)**: the reference of the TreeKnit paper in Chicago author-date style (journal in italics, DOI link) or as BibTeX, with a copy button that also puts HTML on the clipboard, so a pasted reference keeps the italics and the link, and links to the open-access article (DOI), its PDF, PubMed Central, and PubMed. The empty workspace shows the whole widget under the drop zone; the header "Cite" button opens it in a popover, and the help page shows it in "How to cite". One publication record in `src/help/citation.ts` derives the formats and the links [[src](../../packages/web/src/help/citation.ts)]
- [x] **Backlinks (new)**: icon links in the header open the source repository and the command-line releases from `version()`; below 640 px they are hidden, and the help page lists both [[src](../../packages/web/src/shell/Header.tsx)]
- [x] **Run time (new)**: the workspace store measures a successful run with a monotonic clock and keeps the duration with the result; the run bar shows "Finished in 4s" and the overview footer the same span, formatted as the two largest units [[src](../../packages/web/src/workspace/store.ts)]
- [x] **Collapsible panes (new)**: the rail and the inspector slide away with a pull tab on their edge or with Ctrl+B and Ctrl+Alt+B (Cmd+B and Cmd+Option+B on a Mac), and the browser remembers whether each is open; while the rail is a pane, the view tabs sit in the header above the center column, each with a tooltip that describes its view or says that it needs a run [[src](../../packages/web/src/shell/Workspace.tsx)]
- [x] **Undo toast (new)**: removing a tree, clearing the workspace, opening a session file, and resetting the settings each take one visible click, and one toast at the bottom center offers to undo the last of them for 10 seconds, with the remaining seconds on its Undo button; the countdown pauses while the pointer or the focus is on the toast [[src](../../packages/web/src/workspace/useUndoToast.ts)]
- [x] **Inspector navigation (new)**: the inspector header clears a selection, and for a leaf or a branch of an MCC shows that MCC; Escape clears the selection in the inspector and the MCC table as in the drawings; the MCC lists take the remaining height [[src](../../packages/web/src/shell/Inspector.tsx)]
- [x] **Local data**: the trees stay in the browser; a link reads remote files only from the addresses it names, and inline data enters a URL only through Copy link, in the fragment
- [x] **Self-hosted assets**: the fonts, styles, scripts, and the WebAssembly module are bundled. The Content Security Policy allows WebAssembly compilation with `'wasm-unsafe-eval'`, and `connect-src 'self' https:` lets links read remote files
- [x] **Hosting**: the workflow `.github/workflows/release.yml` deploys the app to GitHub Pages every night, from relative asset paths that work under any path. `just run-web prod` builds and serves it locally
