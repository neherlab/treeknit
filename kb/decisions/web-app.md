# Web app with a WebAssembly build of the core

TreeKnit.jl has no browser version. `packages/treeknit-wasm` compiles `treeknit-core` and `treeknit-io` to WebAssembly, and `packages/web` is a React app that runs an analysis in the browser and offers the result files for download. The trees never leave the browser.

## Decisions

- **One thread.** Browsers give WebAssembly threads only on cross-origin isolated pages (`COOP`/`COEP` headers) and with the standard library rebuilt by nightly Rust. The app runs pairs sequentially (`Options::parallel = false`). Without threads, rayon's global pool falls back to the calling thread, so the parallel path also works; `packages/treeknit-wasm/tests/wasm.rs` checks that it gives the same MCCs
- **No OS entropy.** The workspace takes `rand` without default features. The core seeds `rand_xoshiro` generators only, and `getrandom` 0.2, which the default features pull in, does not compile for `wasm32-unknown-unknown`
- **Validated requests, replaceable worker.** A panic traps the WebAssembly instance and leaves it unusable. `Session.run` applies the checks of `treeknit_io::analysis` before the core runs, so it rejects the inputs on which `treeknit_core::run` asserts (fewer than two trees, sequence lengths that do not match the trees) and the settings the command line rejects or that have no meaning (zero rounds, negative or non-finite γ, non-positive sequence lengths, duplicate labels). It throws an `Error` named `ValidationError`, so the app tells an invalid request from an internal failure. The app runs the module in a Web Worker and replaces the worker after a trap or a failed start, so a panic from a defect costs the analysis but not the page
- **Session object.** `Session.run` returns a `Session` that keeps the run result (the input, resolved, and imputed trees, the MCCs, the ARG) and its output files in WebAssembly memory. The app asks it for the summary, a file, or the archive when it needs them, so a run crosses the boundary once and large file texts are copied only on request. The display data and figures read from the same run result
- **Captured log.** The `log` records of Rust have no destination in a browser. A logger of `treeknit-wasm` keeps the records of level Debug and above in a thread-local buffer, with an RFC 3339 time from the JavaScript clock. A run turns them into `log.txt`, in the layout of the command-line log without the thread ID because the browser runs one thread, and into its diagnostics (the warnings and errors). Every other export clears the buffer when it starts and when it ends, so its records never enter the log of a run. The start function installs the logger, and each export installs it too, because `wasm-bindgen-test` does not run the start function
- **Rust owns the data.** The request and result types are Rust types. The session lists the output files of the command line under their command-line names, with the session file, `parameters.json`, and `log.txt`; the default settings come from `defaultSettings()`. The app renders them and neither parses TreeKnit output nor knows its file names, so the command line and the app cannot drift apart
- **Generated TypeScript types.** tsify derives the TypeScript declarations of the request and result types, and wasm-bindgen writes them into `packages/treeknit-wasm/pkg/treeknit_wasm.d.ts`. The declarations are committed, so the TypeScript checks run without a Rust build; `just generated-check` fails when they are stale
- **JSON at the boundary.** Requests and results cross the JavaScript boundary as JSON text and are parsed with `serde_json`, whose errors give the expected type and the position. `serde-wasm-bindgen` reports a wrong field type as an opaque `TypeError`; tsify's `Ts<T>` wrapper keeps the conversion inside the exported function, where a failure is an ordinary error
- **Three worker roles.** The page never runs WebAssembly on its main thread, so a long run does not block input or drawing. The module is compiled once and instantiated in each worker (`packages/web/src/analysis/client.ts`):
  - a utility worker answers the stateless calls (default settings, settings schema, tree inspection, overlap, validation, session files, labels, version, palette, drawing rules). It holds no run, so it stays responsive during a run and is replaced after a trap
  - each run gets its own job worker. Cancel terminates that worker, which stops a run of any length at once, and a late progress message or result of a cancelled run is ignored by its run ID
  - a job worker whose run succeeds becomes the session worker, which keeps the `Session` and answers the summary, file, view, and figure calls. The next successful run replaces it, so one run result is in memory at a time
- **Display data from Rust.** The drawings (tanglegram, ARG, constellation table, Auspice datasets) are built by `treeknit_io::display` from the run result: layout coordinates, node and leaf order, MCC color slots, shortened labels, shapes, and the drawing rules (line widths, opacities, label thresholds, column shares). The web app projects and renders them with deck.gl and holds no layout, color, or label rule, so the SVG figures of the command line and the drawings in the app agree
- **Opt-in persistence.** The workspace stays in memory unless the user turns on "Keep my workspace in this browser". The switch stores the session file and the tree sources in one IndexedDB record (`idb-keyval`), saved 500 ms after the last edit and at once when the page becomes hidden. Turning it off replaces the record with one that holds no trees. A generation number lets tabs coordinate: turning the switch on in one tab turns it off in the others. Trees are research data, so nothing is stored without the user's choice, and nothing leaves the browser
- **Typed worker calls.** comlink exposes the worker functions as a typed asynchronous interface, so the app has no hand-written message protocol
- **Pinned tools.** `wasm-bindgen-cli`, `binaryen` (`wasm-opt`), Node, and Bun come from `.config/mise.toml` with locked checksums, and `rust-toolchain.toml` adds the `wasm32-unknown-unknown` target. `wasm-pack` would download unverified `wasm-bindgen` and `wasm-opt` binaries at build time
- **Auspice embedded as a library.** The Auspice view runs Auspice's own React components and Redux reducers inside the app, as TreeTime's web app does, next to the app's own tanglegram and ARG view, which draw what Auspice does not: MCC ribbons, reassortment marks, and the ARG. Auspice publishes no library build, so the app imports its source modules (`auspice/src/...`), and the Vite plugin `packages/web/build/auspice.ts` compiles their JSX and legacy decorators, pre-bundles the imported entries, and replaces Auspice's timing module with no-op timers, which only Auspice's own Babel build removes. Auspice's URL middleware stays out, because the app's router owns the URL. Each pair, version, and scale builds a new store from datasets that Rust builds, so the TypeScript code holds no dataset or palette logic
- **License.** Auspice is licensed under the AGPL-3.0. The repository's own code stays MIT; the built web app bundle contains AGPL-3.0 code and is distributed under its terms. The help page names Auspice, its license, and the repository with the complete source, including the patch
- **`define` for Auspice's constants.** The project reads client configuration through `import.meta.env.VITE_*`. Auspice's source reads `process.env.EXTENSION_DATA`, `process.env.SKIP_REDUX_CHECKS`, and `process.env.ENABLE_SERVICE_WORKER`; these are constants of a third-party module, not app configuration, and only Vite `define` replaces them in third-party code. The plugin sets them to the values of Auspice's own webpack build, with the empty string as "unset"
- **Patch `patches/auspice@3.0.0.patch`.** Changes made with `bun patch auspice@3.0.0` and `bun patch --commit node_modules/auspice` in the container; several follow the Auspice patch of Nextclade's web app. Each is to drop when an Auspice release makes it unnecessary:
  - `src/components/tree/phyloTree/grid.js`: at least one interval of the time grid. Below 130 px of axis width the interval count is 0, the grid step becomes infinite, and the browser freezes ([nextstrain/auspice#1363](https://github.com/nextstrain/auspice/issues/1363)). TreeKnit datasets have no dates, so this protects against a later dataset change; drop it when a release fixes the issue
  - `src/components/tree/tree.tsx` and `phyloTree/` (`dispose()`, `disposed`): the unmount disposes both trees, whose staged drawing steps (`modifySVGInStages`) and delayed tip labels (`updateTipLabels`) then do nothing, and removes the SVG content of both trees. `StrictMode` mounts the view twice on the same DOM, and a new dataset mounts a new view; without this, a pending step of the old tree draws into the new one. Drop it when a release clears the SVG and stops pending drawing on unmount
  - `phyloTree/change.ts`: no animation when the SVG size changes. The SVG takes its new size at once, so an animation starts from positions computed for the old size and draws the tree out of place; drop it when a release skips the transition on resize
  - `phyloTree/grid.js`: an x-axis label that would cross the SVG edge is anchored at its start or end, except in the radial layout; drop it when a release keeps axis labels inside the SVG
  - `phyloTree/layouts.ts`, `labels.js`, `renderers.ts`, `change.ts`: the rectangular layout widens its left margin for visible branch labels (`fitBranchLabelsInLeftMargin()`, up to a quarter of the width), the clip area covers that margin, and a branch-label change maps the tree to the screen again. Without it the MCC label of a branch near the root is cut off; drop it when a release keeps branch labels inside the SVG
  - `phyloTree/grid.js`, `labels.js`, `renderers.ts`: one clip path per tree (`treeClip-LEFT`, `treeClip-RIGHT`). Both trees used the id `treeClip`, so the right tree was clipped to the rectangle of the left one; drop it when a release gives each tree its own clip path
  - `src/components/tree/tangle/index.js`: the redraw timer of the tangle lines is cleared on unmount and reset when it fires, so it never draws into a removed SVG and each resize removes the old lines; drop it when a release clears the timer
  - `src/components/tree/tree.tsx`, `types.ts`: the own props `showTreeButtons` and `showNodeClickedPanel`. The app passes `false` for both: its header draws one set of zoom buttons for both trees, and its inspector shows a clicked node instead of Auspice's detail panel. Drop them when a release lets an embedding app hide both
  - `src/components/tree/tree.tsx`, `reactD3Interface/initialRender.ts`, `phyloTree/grid.js`, `infoPanels/hover.js`: the own prop `axisTitle`, which names the divergence values on the axis and in the hover panel instead of Auspice's guess between "Divergence" and "Mutations". TreeKnit's branch scales are divergence and depth, which the guess cannot tell apart; drop it when a release reads the axis title from the dataset
  - `src/components/controls/toggle.js`: the checkbox of a toggle is transparent instead of `display: none`, and the slider shows a focus ring, so the keyboard reaches the toggles; drop it when a release makes the toggles focusable
  - `src/components/controls/` (`color-by.js`, `choose-branch-labelling.js`, `choose-tip-label.js`, `filter.js`) and `src/components/info/filterBadge.js`: accessible names for the dropdowns and for the badge buttons ("Hide filter …", "Show filter …", "Remove filter …"), which also run on Enter and Space; drop them when a release names these controls
- **One React and one styled-components.** Auspice declares React 16 and styled-components 4. The root `overrides` set React and its types to the catalog version and styled-components to 5.3.11, so Bun installs one copy, which Auspice's components need inside the app's React tree
- **One Auspice view per page.** Auspice's downloads find the drawings by fixed element ids, so the view tabs mount at most one Auspice view
- **Lato, with Noto Sans as fallback, and IBM Plex Mono for code.** The app text, the canvas labels, the Auspice view, and the SVG figures use Lato, the font of Nextclade and Nextstrain, so the Auspice view looks like those apps. Fontsource's Lato covers only Latin and Latin Extended, so Noto Sans follows it in every font stack for the letters that Lato lacks, such as the settings label "γ" and Cyrillic strain names. Noto Sans is a humanist sans serif like Lato and has its weights 400 and 700, and its unicode ranges load a subset only when a text needs it. Lato has no monospace cut, so code stays in IBM Plex Mono
