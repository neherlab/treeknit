# Web app with a WebAssembly build of the core

TreeKnit.jl has no browser version. `packages/treeknit-wasm` compiles `treeknit-core` and `treeknit-io` to WebAssembly, and `packages/web` is a React app that runs an analysis in the browser and offers the result files for download. The trees never leave the browser.

## Decisions

- **One thread.** Browsers give WebAssembly threads only on cross-origin isolated pages (`COOP`/`COEP` headers) and with the standard library rebuilt by nightly Rust. The app runs pairs sequentially (`Options::parallel = false`). Without threads, rayon's global pool falls back to the calling thread, so the parallel path also works; `packages/treeknit-wasm/tests/wasm.rs` checks that it gives the same MCCs
- **No OS entropy.** The workspace takes `rand` without default features. The core seeds `rand_xoshiro` generators only, and `getrandom` 0.2, which the default features pull in, does not compile for `wasm32-unknown-unknown`
- **Validated requests, replaceable worker.** A panic traps the WebAssembly instance and leaves it unusable. `Session.run` applies the checks of `treeknit_io::analysis` before the core runs, so it rejects the inputs on which `treeknit_core::run` asserts (fewer than two trees, sequence lengths that do not match the trees) and the settings the command line rejects or that have no meaning (zero rounds, negative or non-finite γ, non-positive sequence lengths, duplicate labels). It throws an `Error` named `ValidationError`, so the app tells an invalid request from an internal failure. The app runs the module in a Web Worker and replaces the worker after a trap or a failed start, so a panic from a defect costs the analysis but not the page
- **Session object.** `Session.run` returns a `Session` that keeps the run result (the input, resolved, and imputed trees, the MCCs, the ARG) and its output files in WebAssembly memory. The app asks it for the summary, a file, or the archive when it needs them, so a run crosses the boundary once and large file texts are copied only on request. The display data and figures read from the same run result
- **Captured log.** The `log` records of Rust have no destination in a browser. A logger of `treeknit-wasm` keeps the records of level Debug and above in a thread-local buffer, with an RFC 3339 time from the JavaScript clock. A run turns them into `log.txt`, in the layout of the command-line log without the thread ID because the browser runs one thread, and into its diagnostics (the warnings and errors). Every other export clears the buffer when it starts and when it ends, so its records never enter the log of a run. The start function installs the logger, and each export installs it too, because `wasm-bindgen-test` does not run the start function
- **Rust owns the data.** The request and result types are Rust types. The session lists the output files of the command line under their command-line names, with the session file, `parameters.json`, and `log.txt`; the default settings come from `defaultSettings()`. The app renders them and neither parses TreeKnit output nor knows its file names, so the command line and the app cannot drift apart
- **Generated TypeScript types.** tsify derives the TypeScript declarations of the request and result types, and wasm-bindgen writes them into `packages/treeknit-wasm/pkg/treeknit_wasm.d.ts`. The declarations are committed, so the TypeScript checks run without a Rust build; `just generated-check` fails when they are stale
- **JSON at the boundary.** Requests and results cross the JavaScript boundary as JSON text and are parsed with `serde_json`, whose errors give the expected type and the position. `serde-wasm-bindgen` reports a wrong field type as an opaque `TypeError`; tsify's `Ts<T>` wrapper keeps the conversion inside the exported function, where a failure is an ordinary error
- **Typed worker calls.** comlink exposes the worker functions as a typed asynchronous interface, so the app has no hand-written message protocol
- **Pinned tools.** `wasm-bindgen-cli`, `binaryen` (`wasm-opt`), Node, and Bun come from `.config/mise.toml` with locked checksums, and `rust-toolchain.toml` adds the `wasm32-unknown-unknown` target. `wasm-pack` would download unverified `wasm-bindgen` and `wasm-opt` binaries at build time
