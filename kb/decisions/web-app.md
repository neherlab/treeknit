# Web app with a WebAssembly build of the core

TreeKnit.jl has no browser version. `packages/treeknit-wasm` compiles `treeknit-core` and `treeknit-io` to WebAssembly, and `packages/web` is a React app that runs an analysis in the browser and offers the result files for download. The trees never leave the browser.

## Decisions

- **One thread.** Browsers give WebAssembly threads only on cross-origin isolated pages (`COOP`/`COEP` headers) and with the standard library rebuilt by nightly Rust. The app runs pairs sequentially (`Options::parallel = false`). Without threads, rayon's global pool falls back to the calling thread, so the parallel path also works; `packages/treeknit-wasm/tests/wasm.rs` checks that it gives the same MCCs
- **No OS entropy.** The workspace takes `rand` without default features. The core seeds `rand_xoshiro` generators only, and `getrandom` 0.2, which the default features pull in, does not compile for `wasm32-unknown-unknown`
- **Validated requests, replaceable worker.** A panic traps the WebAssembly instance and leaves it unusable. `Session.run` applies the checks of `treeknit_io::analysis` before the core runs, so it rejects the inputs on which `treeknit_core::run` asserts (fewer than two trees, sequence lengths that do not match the trees) and the settings the command line rejects or that have no meaning (zero rounds, negative or non-finite γ, non-positive sequence lengths, duplicate labels). It throws an `Error` named `ValidationError`, so the app tells an invalid request from an internal failure. A request or figure options with a malformed structure, such as a wrong type or an unknown field, also throw `ValidationError`, with the path of the field from `serde_path_to_error`, and `validate` returns that error in its list. The field of a validation error is a typed `Field` (a tsify enum such as `{ kind: "treeNewick", index: 0 }`): TypeScript compares field values, and the command line prints the path, such as `trees[0].newick`. The app runs the module in a Web Worker and replaces the worker after a trap or a failed start, so a panic from a defect costs the analysis but not the page. The panic reaches the user as a `RuntimeError` whose message is the panic text: the panic hook passes the text to a sink that the worker registers with `setPanicSink`, and the worker's comlink error serializer puts it into the message. The hook returns instead of throwing, because the standard library calls no hook for a later panic in the same instance until the hook returns. A crash without panic text, such as running out of memory (`handle_alloc_error` never reaches the hook, and the shipped build has no function names), gets a message that names the likely cause, followed by the engine message. Catchable panics (`panic=unwind` with wasm-bindgen's `PanicError`) need nightly Rust and `-Zbuild-std` today; they are worth revisiting when Rust stabilizes WebAssembly exception handling ([rust-lang/rust#118168](https://github.com/rust-lang/rust/issues/118168))
- **Session object.** `Session.run` returns a `Session` that keeps the run result (the input, resolved, and imputed trees, the MCCs, the ARG) and its output files in WebAssembly memory. The app asks it for the summary, a file, or the archive when it needs them, so a run crosses the boundary once and large file texts are copied only on request. The display data and figures read from the same run result
- **Captured log.** The `log` records of Rust have no destination in a browser. A logger of `treeknit-wasm` keeps the records of level Debug and above in a thread-local buffer, with an RFC 3339 time from the JavaScript clock. A run turns them into `log.txt`, in the layout of the command-line log without the thread ID because the browser runs one thread, and into its diagnostics (the warnings and errors). Every other export clears the buffer when it starts and when it ends, so its records never enter the log of a run. While a run holds its guard, the buffer stays: an export that a progress callback calls logs into the run instead of erasing its records, and a run started from a progress callback throws, because it would take the outer run's records. Only the start function installs the logger; the tests call it through their helper `ts()`, because `wasm-bindgen-test` does not run the start function
- **Rust owns the data.** The request and result types are Rust types. The session lists the output files of the command line under their command-line names, with the session file, `parameters.json`, and `log.txt`; the default settings come from `defaultSettings()`. The app renders them and neither parses TreeKnit output nor knows its file names, so the command line and the app cannot drift apart
- **Generated TypeScript types.** tsify derives the TypeScript declarations of the request and result types, and wasm-bindgen writes them into `packages/treeknit-wasm/pkg/treeknit_wasm.d.ts`. The declarations are committed, so the TypeScript checks run without a Rust build; `just generated-check` fails when they are stale. A field that serde skips takes `skip_serializing_if = "Option::is_none"` and no other predicate, because tsify marks a field optional only for that exact path and would declare a field required that is absent at runtime. `just gen` also writes `treeknit_variants.ts`, the value lists of the enums whose values the app needs at runtime (tree versions, branch scales, label modes), from `strum::VariantArray` and the serializer of the boundary, and `just generated-check` compares it too
- **JSON at the boundary.** Requests and results cross the JavaScript boundary as JSON text and are parsed with `serde_json`, whose errors give the expected type and the position. `serde-wasm-bindgen` reports a wrong field type as an opaque `TypeError`; tsify's `Ts<T>` wrapper keeps the conversion inside the exported function, where a failure is an ordinary error. A result with a NaN or infinite number is an error that names the type and the field, because `serde_json` would write the number as `null`, which the TypeScript type `number` does not admit. Integer arguments, the pair index and the tree count, cross as tsify newtypes that serde checks, because wasm-bindgen converts a number for a `usize` parameter with ToInt32 and no check, so `NaN`, `0.9`, or 2³² would silently select pair 0
- **Three worker roles.** The page never runs WebAssembly on its main thread, so a long run does not block input or drawing. The module is compiled once and instantiated in each worker (`packages/web/src/analysis/client.ts`):
  - a utility worker answers the stateless calls (default settings, settings schema, tree inspection, overlap, validation, session files, labels, version, palette, drawing rules). It holds no run, so it stays responsive during a run and is replaced after a trap
  - each run gets its own job worker. Cancel terminates that worker, which stops a run of any length at once, and a late progress message or result of a cancelled run is ignored by its run ID
  - a job worker whose run succeeds becomes the session worker, which keeps the `Session` and answers the summary, file, view, and figure calls. The next successful run replaces it, so one run result is in memory at a time

  Each connection to a worker runs one call at a time. A call whose abort signal fires while it waits does not run; React Query aborts a query that has lost its last observer, so outdated validations do not delay current ones. A call that has started runs to the end, because terminating the utility worker on each abort would restart it on every keystroke. After a worker failure the connection starts no queued call and rejects it with the same error, because a trapped WebAssembly instance keeps answering calls with broken state. wasm-bindgen's abort guard would also block such calls, but it needs WebAssembly exception handling with `exnref`, which raises the browser minimum to Chrome 137, Firefox 131, and Safari 18.4
- **Display data from Rust.** The drawings (tanglegram, ARG, constellation table, Auspice datasets) are built by `treeknit_io::display` from the run result: layout coordinates, node and leaf order, MCC color slots, shortened labels, shapes, and the drawing rules (line widths, opacities, label thresholds, column shares). The web app projects and renders them with deck.gl and holds no layout, color, or label rule, so the SVG figures of the command line and the drawings in the app agree
- **Opt-in persistence.** The workspace stays in memory unless the user turns on "Keep my workspace in this browser". The switch stores the session file and the tree sources in one IndexedDB record (`idb-keyval`), saved 500 ms after the last edit and at once when the page becomes hidden. Turning it off replaces the record with one that holds no trees. A generation number lets tabs coordinate: turning the switch on in one tab turns it off in the others. Trees are research data, so nothing is stored without the user's choice, and nothing leaves the browser
- **Typed worker calls.** comlink exposes the worker as a typed asynchronous interface, so the app has no hand-written message protocol. The worker offers the generated module namespace without the exports that only the worker calls (`WORKER_ONLY_EXPORTS` in `packages/web/src/analysis/protocol.ts`), and the `Session` of the current run. The client offers `stateless(operation)` and `inSession(sessionId, operation)`, so a new Rust export needs no TypeScript change outside its callers. An operation may make several calls through the object it receives, but must not call the client, because a nested call on the same connection would wait for the slot that its own operation holds
- **Pinned tools.** `wasm-bindgen-cli`, `binaryen` (`wasm-opt`), Node, and Bun come from `.config/mise.toml` with locked checksums, and `rust-toolchain.toml` adds the `wasm32-unknown-unknown` target. `wasm-pack` would download unverified `wasm-bindgen` and `wasm-opt` binaries at build time
- **Auspice embedded as a library.** The Auspice view runs Auspice's own React components and Redux reducers inside the app, as TreeTime's web app does, next to the app's own tanglegram and ARG view, which draw what Auspice does not: MCC ribbons, reassortment marks, and the ARG. Auspice publishes no library build, so the app imports its source modules (`auspice/src/...`), and the Vite plugin `packages/web/build/auspice.ts` compiles their JSX and legacy decorators, pre-bundles the imported entries, and replaces Auspice's timing module with no-op timers, which only Auspice's own Babel build removes. Auspice's URL middleware stays out, because the app's router owns the URL. Each mount builds a new store from datasets that Rust builds, so the TypeScript code holds no dataset or palette logic
- **License.** Auspice is licensed under the AGPL-3.0. The repository's own code stays MIT; the built web app bundle contains AGPL-3.0 code and is distributed under its terms. The help page names Auspice, its license, and the repository with the complete source, including the patch
- **`define` for Auspice's constants.** The project reads client configuration through `import.meta.env.VITE_*`. Auspice's source reads `process.env.EXTENSION_DATA`, `process.env.SKIP_REDUX_CHECKS`, and `process.env.ENABLE_SERVICE_WORKER`; these are constants of a third-party module, not app configuration, and only Vite `define` replaces them in third-party code. The plugin sets them to the values of Auspice's own webpack build, with the empty string as "unset"
- **Patch `patches/auspice@3.0.0.patch`.** Changes made with `bun patch auspice@3.0.0` and `bun patch --commit node_modules/auspice` in the container; several follow the Auspice patch of Nextclade's web app. Each is to drop when an Auspice release makes it unnecessary:
  - `src/components/tree/phyloTree/grid.js`: at least one interval of the time grid. Below 130 px of axis width the interval count is 0, the grid step becomes infinite, and the browser freezes ([nextstrain/auspice#1363](https://github.com/nextstrain/auspice/issues/1363)). TreeKnit datasets have no dates, so this protects against a later dataset change; drop it when a release fixes the issue
  - `src/components/tree/tree.tsx` and `phyloTree/` (`dispose()`, `disposed`): the unmount disposes both trees, whose staged drawing steps (`modifySVGInStages`) and delayed tip labels (`updateTipLabels`) then do nothing, and removes the SVG content of both trees. `StrictMode` mounts the view twice on the same DOM, and a new dataset mounts a new view; without this, a pending step of the old tree draws into the new one. Drop it when a release clears the SVG and stops pending drawing on unmount
  - `phyloTree/change.ts`: no animation when the SVG size changes. The SVG takes its new size at once, so an animation starts from positions computed for the old size and draws the tree out of place; drop it when a release skips the transition on resize
  - `phyloTree/grid.js`: an x-axis label that would cross the SVG edge is anchored at its start or end, except in the radial layout; drop it when a release keeps axis labels inside the SVG
  - `phyloTree/layouts.ts`, `labels.js`, `renderers.ts`, `change.ts`: the rectangular layout widens its left margin for visible branch labels (`fitBranchLabelsInLeftMargin()`, up to a quarter of the width), the clip area covers that margin, and a branch-label change maps the tree to the screen again. Without it the MCC label of a branch near the root is cut off; drop it when a release keeps branch labels inside the SVG
  - `phyloTree/grid.js`, `labels.js`, `renderers.ts`: one clip path per tree (`treeClip-LEFT`, `treeClip-RIGHT`). Both trees used the id `treeClip`, so the right tree was clipped to the rectangle of the left one; drop it when a release gives each tree its own clip path
  - `src/components/tree/tangle/index.js`: the redraw timer of the tangle lines is cleared on unmount and reset when it fires, so it never draws into a removed SVG and each resize removes the old lines; drop it when a release clears the timer
  - `src/components/tree/tree.tsx`, `types.ts`: the own props `showTreeButtons` and `showNodeClickedPanel`. The app passes `false` for both: its header draws one set of zoom buttons for both trees, and its inspector shows a clicked node instead of Auspice's detail panel. Drop them when a release lets an embedding app hide both
  - `src/components/tree/tree.tsx`, `reactD3Interface/initialRender.ts`, `phyloTree/grid.js`, `infoPanels/hover.js`: the own prop `axisTitle`, which names the divergence values on the axis and in the hover panel instead of Auspice's guess between "Divergence" and "Mutations". TreeKnit's branch scales are divergence and depth, which the guess cannot tell apart; drop it when a release reads the axis title from the dataset
  - `src/components/controls/toggle.js`: the checkbox of a toggle is transparent instead of `display: none`, and the slider shows a focus ring, so the keyboard reaches the toggles; drop it when a release makes the toggles focusable
  - `src/components/controls/` (`color-by.js`, `choose-branch-labelling.js`, `choose-tip-label.js`, `filter.js`) and `src/components/info/filterBadge.js`: accessible names for the dropdowns and for the badge buttons ("Hide filter …", "Show filter …", "Remove filter …"), which also run on Enter and Space; drop them when a release names these controls
  - `src/components/download/helperFunctions.js`: an optional `caption` argument of `SVG()`, whose lines replace the text that Auspice writes below a figure for Nextstrain datasets ("Last updated", the download address and time, the Nextstrain data-use and CC-BY lines). That text does not hold for the trees of a TreeKnit user, and the datasets have no update date; drop it when a release lets an embedding app give the figure text
- **One React and one styled-components.** Auspice declares React 16 and styled-components 4. The root `overrides` set React and its types to the catalog version and styled-components to 5.3.11, so Bun installs one copy, which Auspice's components need inside the app's React tree
- **One Auspice view per page.** Auspice's downloads find the drawings by fixed element ids, so the view tabs mount at most one Auspice view
- **One Auspice store per mount.** The Auspice view builds its Redux store once per mount, in a `useState` initializer, from the datasets and the URL parameter `auspice`. It mounts again (a new `key`) for each new set of datasets and each change of the shown trees: the query cache keeps the old datasets as placeholder data while new ones load, and a new store reaching Auspice's mounted tree component crashed it, because its drawn trees held nodes of the old datasets. The user's Auspice choices survive a remount through the URL parameter
- **Auspice selection from the workspace.** The workspace selection is the single owner of what is selected; the Auspice view reflects it with Auspice's own marks (the tip selection and strain filter of a leaf, the MCC filter of an MCC) and removes them as Auspice's node panel would, and its actions carry a marker so that they do not come back as workspace selections. Auspice's node panel stays hidden, because the inspector shows the selection
- **Lato, with Noto Sans as fallback, and IBM Plex Mono for code.** The app text, the canvas labels, the Auspice view, and the SVG figures use Lato, the font of Nextclade and Nextstrain, so the Auspice view looks like those apps. Fontsource's Lato covers only Latin and Latin Extended, so Noto Sans follows it in every font stack for the letters that Lato lacks, such as the settings label "γ" and Cyrillic strain names. Noto Sans is a humanist sans serif like Lato and has its weights 400 and 700, and its unicode ranges load a subset only when a text needs it. Lato has no monospace cut, so code stays in IBM Plex Mono
- **Path routes with one HTML file per page.** GitHub Pages serves `/x` from `x.html` and has no rewrite rules, so the build writes `help.html` as a copy of the built `index.html`, and the router uses browser history. Hash routing joined a real query string, which sites add to outbound links (`fbclid`, `utm_source`), with the hash route and lost the view keys. The base path is the directory above the entry chunk (`new URL("../", import.meta.url)`), so one build works on GitHub Pages, on the Pages site of a fork, and in the dev server
- **Rust owns the link grammar.** `treeknit_io::launch` reads and writes the keys of links for the web app and the command line, with errors at their keys, so a link and a command translate one to one and the setting names cannot drift: the keys are the long flags, and a unit test of the command line checks them against the key table. The router of the web app reads and writes the query of its address synchronously on every navigation, so it keeps a copy of the query grammar (`readQuery`, `writeQuery`, `linkEntries`); `examples/link_cases.rs` writes a table of pairs with every character that the grammar escapes or keeps, query texts, and links, with the outputs of `link_query`, `query_pairs`, and `link_pairs`, `just gen` commits it, `just generated-check` keeps it current, and one TypeScript test checks the copy against it
- **Remote files need CORS.** The browser reads a remote file only when its host sends `Access-Control-Allow-Origin`; GitHub Pages runs no server code, and a proxy would leak into shared links. The parser rewrites the GitHub and Zenodo page addresses that users copy to the file addresses that send the header, and a failed read names CORS as a possible reason and suggests dropping the downloaded file. `connect-src 'self' https:` allows these reads; `http:` stays blocked
- **A link replaces the workspace with an undo entry.** Opening a link is the user's action, so the app replaces the workspace once every input has loaded, without a confirmation dialog, and Undo brings the previous workspace back. A failed or loading link leaves the workspace and the address bar unchanged, so a reload retries it
- **The address bar is a projection of the store.** After a launch, the store owns the trees and settings and the address bar shows the canonical link of the shown result, so copying the address shares the result: a run is a deterministic function of the trees, the settings, and the seed, and needs no server that stores results
- **Inline data only in the fragment.** The whole URL enters browser history and history sync, so research data enters a URL only through Copy link, as a gzip-compressed session file in the fragment, which no server receives and which the 8 KB request limit of GitHub Pages does not cover. The address bar never holds an inline session
