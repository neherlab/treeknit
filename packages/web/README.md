# treeknit-web

The TreeKnit web app: a React page that runs analyses in the browser on the WebAssembly build of the core (`packages/treeknit-wasm`). The trees never leave the browser.

```sh
just build-web dev    # unminified build with source maps, into dist/
just build-web prod   # build as shipped
just run-web dev      # Vite dev server with hot reload
just run-web prod     # build as shipped, then serve it
```

The commands are the same in the main checkout and in a worktree; `run-web` prints the URL on the port of the checkout. The developer guide (`docs/dev/developer_guide.md`, section "Web app") describes the modes, the ports, and the use of the build container.

## Structure

- `src/main.tsx`: the start-up: fonts, styles, the theme provider (`next-themes`, following the system theme until the user switches, with the settings `THEME_PROVIDER_PROPS` of `src/shell/theme.ts`), and the router
- `src/router.tsx`: the routes `/` (workspace) and `/help`, on hash history so that the app works on any static host without rewrites; search params are plain `key=value` text, and default values stay out of the URL
- `src/workspace/search.ts`: the workspace search params (`view`, `pair`, `version`, `x`, `labels`, `mcc`, `leaf`, `node`) as a zod schema whose invalid or missing values fall back to the defaults; `resolveWorkspaceSearch` replaces values that do not fit the workspace (an unavailable view shows the overview, a pair out of range becomes 0, an `mcc`, `leaf`, or `node` absent from the pair is dropped) from a `WorkspaceAvailability`; `selectPair` clears `mcc` and `node`, because they mean nothing in another pair. A node is written as its side and name, `left:NODE_3`
- `src/workspace/useWorkspaceSearch.ts`: the resolved search params of the workspace and their update; the URL keeps the values as written, so a shared link still applies once the result exists
- `src/shell/`: the application frame: the header (wordmark, "Workspace" and "Help", theme toggle) and the workspace grid of a 336 px rail, the center with the view tabs, and a 320 px inspector. Below 1024 px the rail opens as a side sheet from "Trees and settings" and the run bar stays at the bottom of the screen; below 1320 px the inspector opens as a side sheet from "Details" (`layout.ts`). `Rail`, `RunBar`, `CenterViews` (with one panel component per view), `EmptyCenter`, and `Inspector` are the slots that the workspace features fill
- `src/inputs/`: adding and editing trees. `useTreeInput` reads dropped, chosen, and pasted trees, the examples, and session files (through Rust `readRequest`), and reports what failed; `TreeActions` holds "Add files", "Paste tree", and "Examples"; `TreeDropZone` accepts dropped and pasted files and Newick text; `TreeList` is the reorderable tree list of the rail, with one `TreeRow` per tree (label, counts from `inspectTree` and `overlap`, status, row menu, sequence length) and the "Removed <label>. Undo" notice; `WorkspaceHeader` holds the persistence switch, the workspace menu ("Open session file", "Clear workspace"), and the restore and undo notices
- `src/persistence/`: "Keep my workspace in this browser". `WorkspacePersistence` stores the session file and the tree sources in one IndexedDB record, with a generation: turning the switch on in one tab starts a new generation and turns the switch off in the other tabs, and tabs that restored the same generation all save, so the last save is kept. A change is saved 500 ms after the last edit, and at once when the page becomes hidden. Each save needs a round trip to the worker for the session file before the IndexedDB write, and browsers do not wait for it when a page closes, so edits of the last moment before closing can be lost
- `src/settings/`: the settings form. The store owns the settings that a run sends; `SettingsFormProvider` (react-hook-form, around the whole app) holds a draft only for a number field without a number, which shows "Enter a number" and leaves the store at its last valid value (`draft.ts`). Clearing, loading a session file, and undo discard the drafts (`resetRevision` of the store). Every default, bound, help text, and applicability comes from Rust `settingsSchema`
- `src/run/`: the run control logic: the reason a run is blocked, the progress text, the failure notices, the problem report link (failure kind, version, browser, and settings, never the error message or the trees), and the Ctrl+Enter or Cmd+Enter shortcut on the workspace. The shortcut ignores keys while a modal dialog is open, the settings sheet of narrow layouts included, because a modal keeps the page behind it inert; a run starts from the run bar or the shortcut after the sheet closes
- `src/overview/`: the overview: the tree table and the matrix of shared leaves before a run; after a run the pair table, the MCCs per pair of more than two trees, the reassortment count or the ARG failure, and "No reassortment found." only when the result proves it (`overviewModel.ts`)
- `src/results/`: the "Files" view (the file list of the run, "Download all (ZIP)", "Save session file", and the command line) and the "Diagnostics" view with the count on its tab
- `src/workspace/fieldErrors.ts`: places each Rust validation error on the field that shows it; errors without a shown field appear above "Run TreeKnit"
- `src/help/HelpPage.tsx`: the help page: the workflow, the resolution modes from the schema, a glossary, privacy, the Auspice view with its credit, license, and source link, other tools, citation (`src/help/citation.ts`, also listed in the Auspice downloads), and the version from Rust `version()`
- `src/index.css`: the Tailwind CSS theme tokens: interface colors, type scale, control radius, and the MCC colors, which the app fills from the Rust palette; the dark values apply under the `dark` class on `html`
- `src/download.ts`: `downloadFile`, the one way the app saves a file: a Blob of the content under an object URL, revoked a minute after the click
- `src/analysis/example.ts`: the examples: a small pair of trees, the real H3N2 tree sets of `data/`, and the simulated cases of `fixtures/sim/`, each tree as its file name and Newick text, one lazily loaded chunk per tree file
- `build/content-security-policy.ts`: the Content Security Policy of the page, and the theme script in the head of `index.html`. `'wasm-unsafe-eval'` lets the page compile WebAssembly. The theme script is the script that `next-themes` renders for `THEME_PROVIDER_PROPS`; it sets the theme class before the first paint, because React does not run a script element that it creates on the client. The built page allows that one inline script by its SHA-256 hash

## UI controls

`src/ui/` holds the controls of the app, one file per component, each built on React Aria Components so that focus, keyboard, overlay, and selection behavior come from the library:

- `Button`: variants `primary`, `secondary` (default), and `quiet`; sizes `md` (32 px), `sm` (28 px), and `xs` (20 px); an optional leading `icon`
- `IconButton`: an icon-only button; its required `label` is both its accessible name and its tooltip
- `DisabledButton`: a button that does nothing and says why: it stays focusable with `aria-disabled`, so its tooltip `reason` reaches keyboard and pointer users, which a disabled React Aria button cannot show
- `TooltipTrigger`: wraps one focusable trigger and shows `tooltip` after 600 ms. With `repeatsName`, the tooltip text equals the accessible name of the trigger and stays out of its description, so that screen readers say it once; `IconButton`, icon-only toggle buttons, and the step buttons of `NumberField` set it
- `InfoButton`: the info icon with the label and tooltip "About <topic>"; it opens a popover dialog with a short explanation
- `TextField` (single line, or `multiline`; `mono` for Newick text, with spell checking, autocorrect, autocapitalize, and autocomplete off), `NumberField` (with step buttons that carry the localized labels of React Aria), `Select` (typed option ids), `RadioGroup` with `Radio`, `Switch`, and `ToggleButtonGroup` with `ToggleButton` (single selection by default; `iconOnly` buttons get a tooltip)
- `InlineNotice`: tones `info`, `warning`, and `danger`, each with its own icon, an optional title, an optional action such as "Undo", and `onDismiss`, which adds a "Dismiss" button named by the tone ("Dismiss error") that returns focus on dismissal to the element that had it when the notice appeared (React Aria `FocusScope restoreFocus`); a danger notice is an alert, which screen readers announce when it appears. `NoticeRegion` is a live region for info and warning notices: it stays mounted while notices come and go inside it, because screen readers usually do not announce a live region that mounts together with its content
- `ProgressBar`: determinate, or a static hatched bar when indeterminate; `labelHidden` hides the label and keeps the value text
- `Tabs` with `TabList`, `Tab`, and `TabPanel`: an underlined tab row on a rule
- `Menu` (with its `trigger`), `MenuItem` (optional `icon`, `tone="danger"`), `MenuSection`, and `MenuSeparator`
- `Dialog`: a modal with a title, a close button, and an optional footer; `placement` `center` (default), or `left` and `right` for a side sheet. Open it from a `DialogTrigger` or with `isOpen` and `onOpenChange`
- `Disclosure`: a section title that expands its content, with an optional info button
- `GridList` with `GridListItem`: rows separated by rules; with `onReorder`, each row has a drag handle, and rows move by pointer or keyboard. `reorder` (`src/ui/reorder.ts`) applies the move to a list
- `Table` with `TableHeader`, `Column`, `TableBody`, `Row`, and `Cell`: a small table in Plex Sans Condensed with a sticky header, sort indicators, and `align="end"` for numbers. Its class strings (`tableStyle`, `tableHeaderStyle`, `columnStyle`, `cellStyle`, `nativeRowStyle`) and `SortIndicator` also style the virtualized HTML tables of `src/tables/`
- `useVirtualRows` and `VirtualGap`: TanStack Virtual rows for the HTML tables of `src/tables/`: the hook measures each rendered row from a 32 px estimate and starts the rows below the measured sticky header, and `VirtualGap` is an `aria-hidden` spacer row that stands for the rows outside the rendered window
- `VirtualList`: a React Aria list box inside a `Virtualizer` with fixed 32 px rows, for long lists of the inspector
- `MccSwatch`: the square of an MCC color slot; a slot outside the palette is an error
- `QueryState`: the progress bar while a query has no data, the error notice when it failed, and otherwise its content
- `PanelBoundary`: the error boundary of one view tab or the inspector, so a value that fails while a panel renders shows a notice with Retry in that panel and leaves the rest of the page working
- `Link`: a router link (TanStack Router `createLink` over the React Aria link), so links take `to` and `search`
- `ExternalLink`: a link to another site, opened in a new tab
- `EmptyState`: a quiet, left-aligned message with an optional icon, details, and actions
- `CodeBlock`: Plex Mono text in a figure named by its caption, in a scroller that takes keyboard focus while its content overflows (WebKit does not focus scroll containers by itself), a copy button that shows "Copied" or "Copy failed" for 2 s (the latest copy wins, and the cause of a failure goes to the console), line numbers for more than one line, and an optional `errorRange` in the danger colors (1-based line and column, columns in Unicode code points, end exclusive), which the scroller scrolls into view without scrolling the page; an empty range shows a caret with the hidden text "Error position". A line end at the end of the text adds no empty line, unless the range is on that line. `codeLines` follows `newick::line_column` of `treeknit-io`, and both test suites check the same cases

Conventions for new controls:

- **Styles**: `src/ui/styles.ts` owns the shared classes: the focus ring, the button variants, the field input, label, description, and error, and the popover, list box, and option styles; `src/ui/Table.tsx` owns the table classes. Variants use `class-variance-authority`, and classes merge with `cn`. Controls use only the theme tokens of `src/index.css`, so both themes follow from the tokens
- **Focus**: a 2 px ring in the focus color with a 2 px offset, on keyboard focus only (`data-focus-visible`, or `:focus-visible` through `nativeFocusRing` for an element without React Aria); text inputs also turn their border to the focus color on any focus
- **States**: hover, pressed, disabled, and invalid come from the React Aria data attributes (`data-hovered`, `data-pressed`, `data-disabled`, `data-invalid`); disabled text uses `ink-muted`
- **Color**: the primary button, a selected toggle, and an on switch are ink with ground text, so the interface stays quiet next to the colored drawings. Signal marks reassortment only and never appears in a control. Errors use danger with the `circle-alert` icon
- **Shape**: 4 px radius (`rounded-control`) on controls, and 2 px (`rounded-inner`) on parts inside a control, such as the thumb of a switch; radio indicators stay round
- **Fields**: a field takes `label`, optional `labelHidden`, `description`, `errorMessage`, and `info`, through the shared parts in `src/ui/Field.tsx`. An `errorMessage` alone marks the field invalid. A field with `labelHidden` takes no `info`, because the info button would have no visible topic
- **Description and info**: `description` is a few words under the field that the user needs while filling it, such as a unit or an input format. Every explanation, such as what a setting does, why it does not apply, or how to read a table, goes into `info`, the popover of the info button, and never into a paragraph in the workspace
- **Icons**: Lucide through `unplugin-icons` (`import InfoIcon from "~icons/lucide/info"`), passed to controls as components (`icon={InfoIcon}`) and always `aria-hidden`
- **Motion**: color changes on hover and the thumb of a switch move in 150 ms and stop under `prefers-reduced-motion`; nothing moves on its own

## Tree canvas

`src/canvas/` holds the drawing engine that every tree drawing uses: one deck.gl canvas whose horizontal axis is fitted to the width and whose leaf axis zooms, as in Auspice. It draws the shapes that Rust lays out (branch elbows, link and ribbon curves, marks) and builds no shape of its own; it only maps their normalized units to the canvas.

- **Coordinates**: world x is in canvas pixels and world y in leaf rows, row `i` at `y = i`, with half a row of margin at both ends. On the narrow layout (`leafAxis` `x`) the two axes swap
- **View state** (`viewState.ts`): pure functions over a `CanvasFrame` (canvas size, row count, leaf axis). The view zooms the leaf axis only, with deck.gl's `zoomX`, `zoomY`, and `zoomAxis`; the cross axis keeps zoom 0 and its center, so a drawing never moves sideways. The leaf zoom stays between the fitted view and 64 px per row, and a zoom that changes the canvas by less than one pixel from either limit snaps to that limit, so rounding in repeated zoom steps never leaves a zoom button enabled without effect. The view stays inside the drawing, and a drawing shorter than the canvas stays centered. `viewStateAt` applies these limits to every change, also to the controller updates of wheel, drag, and keyboard. The deck.gl 9.4 `OrthographicController` option `maxBounds` does not replace it: without `rubberBand` it pins a drawing shorter than the canvas to its starting edge instead of centering it, `rubberBand` adds an elastic overscroll the drawing does not use, and the toolbar, fit, clade, and minimap actions do not pass through the controller. `fitRowsViewState` frames a row range (the clade zoom)
- **View store**: the view of one drawing lives in a small zustand store (`createTreeViewStore`), changed by a pure reducer (`treeViewReducer`) behind stable `actions` (resize, controller update, zoom in, zoom out, fit, fit rows, pan to a row, pan by a row offset). The panel holds the store, its drawing (row count and leaf axis), and the actions as a `TreeViewHandle` (`useDrawingView`) without reading the view, so a pan or zoom frame renders only the canvas (`useTreeView`) and the zoom buttons (`useZoomRoom`), not the toolbar. A new row count or leaf axis fits the drawing again; a resize keeps the visible rows
- **`TreeCanvas`**: the `DeckGL` element with an `OrthographicView`. Wheel and pinch zoom around the pointer, drag pans, and the arrow keys and `+`/`-` pan and zoom while the drawing has focus. A double-click asks `onCladeZoom` for the row range of the picked branch and frames it; Enter asks `onSelectionZoom` for the row range of the selection (`pairSelectionRows`, `argSelectionRows`: the leaves under a selected node, both copies of a selected leaf, or the leaves of a selected MCC in both trees) and frames it, the keyboard equivalent of the double-click. The container is focusable and has `role="application"` with `aria-roledescription="tree drawing"`, the ARIA pattern for an element that handles its own keys, so screen readers in browse mode pass the arrow and `+`/`-` keys to the drawing; it also has the drawing's label and a description that lists the keys and points to the tables. Without WebGL 2 it shows a notice instead. It renders inside `CanvasBoundary`: deck.gl errors (`onError`, such as a lost WebGL context or a failing layer) and a failed clade pick show the boundary's error notice; create the view store outside the boundary (`useDrawingView` in the panel) to keep the view across "Retry"
- **`Minimap`**: for more than 200 leaves and a drawing at least 400 px long, a strip beside the drawing, 112 px across the cross axis and as long as the drawing along the leaf axis (`minimapSize`), shows the whole drawing and the visible rows; pressing or dragging on it moves the main view. The strip takes its width from the drawing instead of covering it: at the right with leaves along y, at the bottom with leaves along x. deck.gl sets the canvas to that size and the strip has a rule on its inner side only; the projection and the pointer mapping use the size deck.gl measures. It takes its own layer instances, because a deck.gl layer belongs to one canvas
- **`ZoomControls`**: the "Zoom in", "Zoom out", and "Fit to view" buttons for a drawing toolbar
- **Projection** (`projection.ts`): a `Column` maps normalized x in 0 to 1 to canvas pixels, mirrored for a tree drawn with its root at the right; the `Point` and `Bezier` shapes are the generated Rust types. A cubic Bézier curve becomes a path by uniform parameter subdivision with exact endpoints; `wangSegmentCount` takes the number of segments from Wang's bound, $n = \lceil \sqrt{\tfrac{3}{4} M / \varepsilon} \rceil$, where $M$ is the largest second difference of the control points in CSS pixels and $\varepsilon$ = 0.5 CSS px is the largest distance between path and curve, with at least one segment and at most 1,024 (`CURVE_SEGMENTS_MAX`). The cap bounds the memory of a curve at 1,025 points; the bound holds below it, which at 64 px per row covers links across up to about 10,900 rows, and a longer curve keeps 1,024 segments and may deviate more than 0.5 px from the curve. $M$ uses the row height of the view rounded up to a power of two (`curveRowPx`), so the bound holds at the shown zoom, and the drawings sample their curves again only when the zoom crosses a power of two. A control point that is not finite throws a `RangeError`
- **Layer builders** (`layers/`): `labelLayer`, `pathLayer`, `markLayer` (rings and circles), and `fillLayer` (solid polygons) turn data and accessors into deck.gl layers; `treeLayers.ts` holds the branch, ring, and selection-ring builders with the stroke widths that the tanglegram and the ARG share, and a hover tint in the focus color. Geometry depends only on the data, the options, and the canvas size; selection and hover change colors through `colorTriggers`, so a hover does not rebuild the paths of 20,000 leaves. Dashed paths use the deck.gl `PathStyleExtension` with dashes in pixels
- **Colors** (`drawingColors.ts`): `useDrawingColors` takes the drawing colors (ground, ink, ink-muted, signal, focus, segments, MCC slots) as RGBA bytes from the theme of the Rust palette that `next-themes` resolves (`paletteTheme`). The Rust palette is the one owner of these colors: the drawings read it through a suspense query behind `CanvasBoundary`, and `PaletteStyles` writes its MCC colors into the CSS variables of the swatches; a Rust test keeps the interface tokens of `src/index.css` equal to it. A failed palette query shows the error notice of `CanvasBoundary`
- **Labels** (`labels.ts`): 12 px IBM Plex Sans Condensed. The thresholds come from the Rust `drawingRules()`, which the canvases read once through `useDrawingRules` (a suspense query behind `CanvasBoundary`), and the pure functions of this module take them as arguments: the `auto` mode shows labels from `labelAutoMinRowPx` (10 px per row), `on` and `off` always and never; a label longer than `labelMaxChars` (40) is shortened in the middle; below `linkMinRowPx` (6 px per row) the tanglegram draws ribbons, from there one curve per link. The text layer waits for the font faces that cover the label characters (`useLabelFontReady(labelCharacters(names))`, which passes the characters to `document.fonts.load`, so the latin-ext and cyrillic subsets load too). A failed font load, or a load that finds no IBM Plex Sans Condensed face, is logged with the font descriptor (`console.error`), and the labels then draw in a fallback font. The text layer builds its glyphs from the data (`characterSet: "auto"`), because strain names hold letters outside ASCII
- **Motion** (`motion.ts`): `useFadeIn` gives the 300 ms opacity ramp of ribbons and links when a new result arrives, and full opacity under `prefers-reduced-motion`
- **Loading** (`lazyCanvas.ts`): deck.gl is large, so a drawing view is a separate chunk: create the lazy component once at module level with `lazyCanvas(() => import(...))`, read it in the panel with `useLazyCanvas`, render it inside `CanvasBoundary`, and pass the returned `reload` as `onReset`. The lazy component lives at module level, so entering the tab again, which mounts the panel again, renders the loaded drawing without suspending. The boundary shows a progress bar while the chunk loads and, if the drawing fails, an error notice with the message and a "Retry" button. "Retry" and a new `resultKey` clear the failure: they reset the failed queries of the drawing (a `QueryErrorResetBoundary`, because a suspense query that failed otherwise throws its cached error again on remount) and call `reload`, which creates a new lazy component, so a chunk that did not load is requested again: `React.lazy` keeps a rejected import and fails at once on every render. Chromium also keeps a failed module import for the page, so there a chunk that did not download loads only after a page reload; the notice of a failed chunk download (`DrawingCodeError`) says so. Modules outside a lazy drawing import only the deck.gl-free parts of `src/canvas/` (view state, colors, labels, motion, zoom controls, `lazyCanvas`)

## Drawings

The tanglegram (`src/tanglegram/`) and the ARG (`src/arg/`) draw the shapes of `pairView` and `argView` on the tree canvas. Each tab has a panel outside the lazy chunk (toolbar, queries, view state, selection) and a canvas module loaded with `lazyCanvas` inside `CanvasBoundary`, so deck.gl stays in its own chunk.

- **Columns**: the tanglegram is five columns across the canvas (`tanglegram/columns.ts`): the left tree, its labels, the link zone, the right labels, and the right tree, mirrored. The link zone takes 20% of the width; the label columns take their width from it down to 15% before the trees narrow, so short labels appear without moving the trees. A label column fits the longest shown label and takes at most a quarter of half the width; it is reserved only while labels show, so a drawing without labels has no empty band between the trees and the link zone; the columns change once when zooming crosses the 10 px label threshold. The ARG is one tree column with its labels at the right (`arg/geometry.ts`), whose label column takes at most a quarter of the inner width
- **Geometry** (`geometry.ts` of each drawing): maps the Rust elbows, curves, outlines, and marks from normalized units to canvas pixels, and sorts branches into plain, dashed (added by resolution, or ARG reticulation), and reassortment branches. Its frame (branches, marks, leaders, labels, node positions) depends only on the data, the columns, and the leaf axis, so it is computed once per result and size; the sampled curves (links, ribbons, ARG edges) are a separate value that the drawings compute again when the zoom crosses a power of two, so a zoom step leaves the data of the other layers unchanged
- **Leaders**: while labels show, a dotted muted line runs from each leaf tip to its label column (the Rust `leaders` shapes), so a label stays readable next to a short branch. Leaders hide with the labels, wait for the label font as the labels do, and fade with the labels of other MCCs when an MCC is selected
- **Layers** (`layers.ts` of each drawing): colors and visibility only. The tanglegram colors branches by MCC slot (or ink-muted when "Color branches by MCC" is off), reassortment branches signal, ribbons at 55% opacity; a selected MCC fades everything else to 25%. ARG edges take the segment A or B color, or ink for both
- **Selection** (`src/drawing/selection.ts`): a click becomes a target (node, link, ribbon, or ARG edge) through the layer id and the picked index, and the target becomes the URL selection: a leaf sets `leaf`, a link or ribbon sets `mcc`, an internal branch sets `node` and its `mcc`, an ARG internal or hybrid node sets `node` with the side `arg`, and the background or Escape clears all three
- **Narrow canvas**: below 640 px canvas width `useDrawingView` swaps the axes, so the trees face each other top and bottom, and no labels are drawn
- **Focus requests** (`src/drawing/focus.ts`): the inspector, the MCC table, and the constellation ask the tanglegram to fit an MCC or a leaf: a leaf in both trees fits both copies, and a leaf in one row pans there and keeps the zoom. The tanglegram applies the request once its data and canvas size exist; a request for a leaf in another pair waits until that pair is shown
- **Shared parts** (`src/drawing/`): the drawing panel frame with its toolbar, loading and error states; the toolbar controls (branch scale, tree version, label mode, "Download figure (SVG)", disabled until the figure download is wired); the legend, a bar above the drawing whose symbols take the colors, widths, and dashes of the drawing layers, so it never covers the trees; the picking rules that map a picked layer item to a tooltip, a selection, and a zoom range (`useDrawingPicking`); the selection and leaf-search callbacks of both panels (`useDrawingSearch`, `useFindLeaf`); the leaf search (React Aria `Autocomplete` with a `SearchField` and a `Menu`, at most 50 matches); and tooltips

## Auspice view

The tab "Auspice" draws the selected pair with [Auspice](https://docs.nextstrain.org/projects/auspice) 3.0.0, the tree viewer of Nextstrain, embedded as a library: its React components and Redux reducers run inside the app. The left tree is Auspice's main tree and the right tree its second tree, so Auspice draws a tanglegram with a line between the two copies of each tip. Auspice is licensed under the AGPL-3.0, so the built app is distributed under the AGPL-3.0; the help page names Auspice, its license, and the source repository.

- **Datasets**: Rust `Session.auspiceView(pair, version, scale)` builds both Auspice datasets (MCC coloring in the light palette, MCC filter, branch labels "MCC" where an MCC starts), so the app passes them to Auspice unchanged
- **Store** (`src/auspice/store.ts`, `src/auspice/useAuspiceStore.ts`): one Redux store per pair, version, and scale, built with Auspice's `createStateFromQueryOrJSONs` from copies of the datasets, because Auspice changes the objects it reads and the query cache keeps the originals. The store has Auspice's reducers and the middlewares `thunk`, `performanceFlags`, and `keepScatterplotStateInSync`, without Auspice's URL middleware, because the app's router owns the URL
- **Selection** (`src/auspice/selection.ts`): a store middleware passes Auspice's `SELECT_NODE` to the workspace selection: a tip, or the branch above a tip, selects the leaf, an internal branch (Shift click in Auspice) selects the node on the side of its tree, and `DESELECT_NODE` clears the selection. Auspice's own strain filter on a tip click stays as Auspice applies it
- **View** (`src/auspice/AuspiceView.tsx`, loaded with `lazyCanvas` from `src/auspice/AuspicePanel.tsx`, so Auspice, Redux, styled-components, and d3 are a separate chunk): Auspice's sidebar (260 px; it stacks above the tree when the tree would get less than 640 px), its filter summary, its downloads behind "Download figure and data", and the tree sized from the measured area. Auspice has no dark theme, so the view keeps the light tokens in the dark theme (the `light-scope` utility of `src/index.css`, with the light MCC colors from `paletteCss`). The view tabs mount at most one Auspice view, because Auspice's downloads find the drawings by fixed element ids
- **Build** (`build/auspice.ts`): Auspice publishes no library build, so the app imports its source modules (`auspice/src/...`). The Vite plugin, registered in `vite.config.ts` and in the root `vitest.config.ts`, compiles their JSX and legacy decorators, pre-bundles the imported entries (`AUSPICE_ENTRIES`), replaces Auspice's timing module with no-op timers, sets the `process.env` constants that Auspice reads through `define`, and dedupes React. A test keeps the entries, the imports of `src/auspice/`, and the type declarations equal
- **Types** (`src/auspice/types/`): one declaration file per imported Auspice module, mapped by `paths` in `tsconfig.json`, because Auspice's TypeScript sources do not type-check under the app's settings. They declare only what the app uses
- **Patch** (`patches/auspice@3.0.0.patch`, root `package.json` `patchedDependencies`): at least one interval of the time grid, and the SVG of both trees cleared on unmount for the second mount of `StrictMode`. The root `overrides` give Auspice the app's React and styled-components 5. `kb/decisions/web-app.md` records when to drop each part

## Inspector and tables

- **Inspector** (`src/shell/Inspector.tsx`, with the pure `src/inspector/subject.ts`): shows the selected node (tree or ARG), else the selected leaf (its copies, MCC, attachment, and its MCC in every pair as links), else the selected MCC (size, members, "Zoom to MCC"), else the MCC list of the pair. Long lists are React Aria list boxes inside a `Virtualizer`
- **MCC table** (`src/tables/MccTablePanel.tsx`): TanStack Table for the columns, sorting, and the leaf-name filter, TanStack Virtual for the rows (`useVirtualRows` measures each rendered row and starts below the sticky header); the table elements take the class strings and the sort indicator of `ui/Table`, and the headers state their sort order in `aria-sort`; a row button selects its MCC and the arrow button shows it in the tanglegram
- **Constellation** (`src/tables/ConstellationPanel.tsx`): one row per leaf with a sticky leaf column and one column per pair (`pairColumns`), virtualized like the MCC table; it has no sorting or filter, so it uses no TanStack Table; a cell opens that pair's tanglegram with the leaf selected. It is a plain HTML table, an exception to the project rule that tables use the React Aria table: it has no grid keyboard navigation, so every cell button is its own Tab stop. Moving it to the React Aria `Table` inside a `Virtualizer` would give arrow-key navigation with one Tab stop

## Data from Rust

The request and result types are Rust types in `packages/treeknit-wasm/src/analysis.rs`. tsify writes their TypeScript declarations into `packages/treeknit-wasm/pkg/treeknit_wasm.d.ts`, which the app imports from `@neherlab/treeknit-wasm`. Validation, default settings, MCCs per pair, and the output files with their command-line names all come from Rust; the app renders them and does not parse TreeKnit files. After changing the interface, run `just gen` and commit the declarations; `just generated-check` fails when they are stale.
